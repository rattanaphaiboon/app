ตัวอย่าง ยังไม่ใช่ของจริง · T-0006-1

ทำไม GitHub ส่งอีเมล "Run failed"

repo rattanaphaiboon/app · ตรวจรอบ run ย้อนหลัง 200 รอบ (2026-11-21 ถึง 2026-11-22)

เกิดอะไรขึ้น

23รอบที่ fail
200รอบที่ตรวจ
113 MBไฟล์ที่ส่งขึ้นเว็บ

ทุกรอบที่ fail ขึ้นข้อความเดียวกันหมด ไม่ใช่โค้ดแอปพัง ไม่ใช่ push ผิด และหน้าเว็บที่ขึ้นอยู่ก็ไม่เสียหาย

Artifact github-pages has been successfully uploaded!
Found 0 artifact(s)
Error: No artifacts named "github-pages" were found

สาเหตุ จังหวะเวลา

  1. 1
    ทุกครั้งที่ push ขึ้น main GitHub จะมัดไฟล์ทั้ง repo (ตอนนี้ ~113 MB) เป็นก้อนเดียวแล้วอัปขึ้นที่เก็บของ GitHub
  2. 2
    อัปเสร็จปุ๊บ ขั้นตอนถัดไปถามหาก้อนนั้นทันทีภายใน 0.4 วินาที เพราะงานทั้งสองอยู่ใน job เดียวกัน ไม่มีช่วงพัก
  3. 3
    ฝั่ง GitHub ขึ้นทะเบียนก้อนไฟล์ช้ากว่านั้นเป็นบางครั้ง เลยตอบว่า "ไม่มีไฟล์" ทั้งที่อัปสำเร็จแล้ว งานจึง fail และส่งอีเมลหาเรา
  4. 4
    เป็นแบบสุ่ม ประมาณ 1 ใน 9 รอบ วันที่ push ถี่ๆ เลยได้อีเมลติดกันหลายฉบับ

ผลกระทบจริง: รอบที่ fail เว็บไม่ได้อัปเดต แต่ push รอบถัดไปจะอัปทับให้เองทั้งหมด จะเสี่ยงก็ต่อเมื่อรอบที่ fail เป็น push สุดท้ายของวัน แล้วไม่มีใครสังเกต เว็บจะค้างของเก่า

จะแก้ยังไงไม่ให้เกิดอีก แก้ที่ไฟล์เดียว

  1. 1
    แยกเป็น 2 ขั้น ขั้นมัดไฟล์กับขั้นเอาขึ้นเว็บแยก job กัน มีระยะห่างตามธรรมชาติ 10-20 วินาที
  2. 2
    ใส่ขั้นรอก่อนเอาขึ้นเว็บ คอยเช็คทุก 5 วินาที จนกว่าจะเห็นก้อนไฟล์จริง (รอสูงสุด 2 นาที) แล้วค่อยไปต่อ
  3. 3
    ไม่ส่งของที่เว็บไม่ได้ใช้ ตัดโฟลเดอร์ backups ออกจากก้อนที่อัป ลดขนาดลง ~15 MB งานเร็วขึ้นและพลาดยากขึ้น

หน้าตาไฟล์ตั้งค่าหลังแก้ (.github/workflows/deploy-pages.yml)

jobs:
  build:
    steps:
      - uses: actions/checkout@v5
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v5

  deploy:
    needs: build
    steps:
      - name: รอจน GitHub ขึ้นทะเบียนไฟล์ก่อน
        run: |
          for i in $(seq 1 24); do
            ... เช็คว่ามี github-pages แล้วหรือยัง
            ถ้ามี -> ไปต่อ / ถ้ายัง -> sleep 5
      - uses: actions/deploy-pages@v5

ไม่เพิ่มเครื่องมือใหม่ ใช้ของเดิมที่ GitHub มีให้อยู่แล้ว · ไม่แตะไฟล์แอปสักตัว · ถ้าอนาคต GitHub ล่มจริงๆ ยังได้อีเมลเตือนเหมือนเดิม

เรื่องอีเมล

พอแก้แล้วอีเมลพวกนี้จะหายไปเอง ไม่ต้องไปปิดการแจ้งเตือน — แนะนำให้เปิดไว้ เพราะถ้าวันไหนแอปขึ้นเว็บไม่สำเร็จจริง จะได้รู้ทันที
